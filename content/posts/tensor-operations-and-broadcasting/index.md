上一篇确认了[张量的 shape 与轴的含义]({{< relref "/posts/tensors-and-shapes" >}})。这一篇继续问：**不同 shape 的张量放在一起运算，究竟比较了哪些位置？**

广播最需要警惕的地方，不是报错，而是计算顺利完成，却悄悄改变了原来的意图。先看规则，再把它与求和、求均值串起来。

## 1. 逐元素运算：对应位置各算各的

两个同形状张量相加、相减、相乘或相除，通常按对应位置计算：

```text
a = [1, 2, 3]       shape: (3,)
b = [10, 20, 30]    shape: (3,)

a + b = [11, 22, 33]
a * b = [10, 40, 90]
```

这是**逐元素运算（element-wise operation）**，结果仍是 `(3,)`。这里用列表形式展示张量里的数，说的是 PyTorch 张量运算，不是 Python 列表的运算规则。

特别记住：**PyTorch 的 `*` 是逐元素乘法，矩阵乘法通常用 `@`**。矩阵乘法留到下一篇。

当另一侧只有一个标量时，这个数参与每个位置的计算：

```text
[1, 2, 3] + 10 = [11, 12, 13]
[1, 2, 3] * 10 = [10, 20, 30]
```

向量的 shape 是 `(3,)`，标量是 `()`，结果为 `(3,)`。这种让不同 shape 按规则配合计算的机制，就是**广播（broadcasting）**。

计算效果像是把 `10` 放到了每个位置，但标量本身没有变成向量；框架也不需要先实际构造出一整排 `10`。

## 2. 广播规则：先对位置，再看长度

判断广播只需要三步：

1. **从右边对齐 shape**，较短的一侧在左边按长度 `1` 补齐，仅用于判断。
2. **逐轴检查**：两个长度相等，或者其中一个为 `1`，才能配合；任意一对不满足，就不能广播。
3. **确定结果长度**：相等时保留该长度；一侧为 `1` 时，取另一侧的长度。

讨论中最容易混淆的是“对齐”这个词：**对齐指轴的位置对上，不是要求长度必须相等。** 右对齐确定哪些轴互相比，后面的规则才决定这些长度能不能算。

例如 `(2, 3)` 与 `(3,)`：

```text
原始 shape：          判断时补齐：
A: (2, 3)            A: (2, 3)
b:    (3,)           b: (1, 3)
```

右边 `3` 与 `3` 相等，左边 `2` 与 `1` 可以广播，所以结果为 `(2, 3)`。补齐只帮助判断，`b` 的实际 shape 仍然是 `(3,)`。

但 `(2, 3)` 与 `(2,)` 不行：最右边比较的是 `3` 与 `2`，既不相等，也没有 `1`。即使左边恰好有一个 `2`，也不能跳过去找它配对。

## 3. 给每列加数，还是给每行加数？

设有一张两行三列的数表：

```text
A = [[1, 2, 3],
     [4, 5, 6]]       shape: (2, 3)
```

加上 shape 为 `(3,)` 的 `[10, 20, 30]`，向量对齐最右边的轴：

```text
A + [10, 20, 30]
= [[11, 22, 33],
   [14, 25, 36]]
```

效果是**每一行都加同一组数**：第一列加 10，第二列加 20，第三列加 30。框架并不知道“这是行向量”，只是在执行 shape 规则。

如果想让第一行全部加 10、第二行全部加 20，应把相加的数据组织成 `(2, 1)`：

```text
c = [[10],
     [20]]            shape: (2, 1)

判断： (2, 3) + (2, 1) → (2, 3)

结果： [[11, 12, 13],
       [24, 25, 26]]
```

此时最右边的 `1` 配合 `3`，同一行的那个数用于三列。**`(2,)` 和 `(2, 1)` 虽然都只有两个元素，却不能互相替代。** 要给四行分别加四个数，相应组织方式就是 `(4, 1)`。

## 4. 高维广播：把具体加法展开看

规则对三个轴、四个轴也一样。以 `(2, 1, 4) + (3, 4)` 为例：

```text
A: (2, 1, 4)
B: (1, 3, 4)    ← 左边补 1 后用于判断
结果：(2, 3, 4)
```

只看 shape 不够直观，可以把 A 看成两张各有一行、四列的表，把 B 看成一张三行四列的表：

```text
A 的第 1 张：[[1, 2, 3, 4]]
A 的第 2 张：[[5, 6, 7, 8]]

B = [[10, 10, 10, 10],
     [20, 20, 20, 20],
     [30, 30, 30, 30]]
```

A 每张表的那一行分别与 B 的三行相加；同一个 B 又分别用于 A 的两张表。结果是：

```text
第 1 张结果：             第 2 张结果：
[[11, 12, 13, 14],       [[15, 16, 17, 18],
 [21, 22, 23, 24],        [25, 26, 27, 28],
 [31, 32, 33, 34]]        [35, 36, 37, 38]]
```

最终是两张三行四列的表，所以 shape 为 `(2, 3, 4)`。这里两个方向都发生了广播：A 的中间轴从长度 1 配合到 3，B 左边补出的轴从长度 1 配合到 2。重复画出行或表只是解释计算效果，不要求真的复制它们。

## 5. 求和与均值：dim 指定被汇总的轴

把多个数汇总起来，叫作**归约（reduction）**。对刚才的二维 A：

```text
A = [[1, 2, 3],
     [4, 5, 6]]       shape: (2, 3)
```

| 操作 | 结果 | shape |
| --- | --- | --- |
| `A.sum()` | `21` | `()` |
| `A.sum(dim=0)` | `[5, 7, 9]` | `(3,)` |
| `A.sum(dim=1)` | `[6, 15]` | `(2,)` |
| `A.mean()` | `3.5` | `()` |
| `A.mean(dim=0)` | `[2.5, 3.5, 4.5]` | `(3,)` |
| `A.mean(dim=1)` | `[2, 5]` | `(2,)` |

这里假设 A 是浮点张量；PyTorch 的普通整数张量需要先转成浮点类型，才能这样调用 `mean()`。

**`dim` 指定沿哪个轴汇总，默认这个轴会从结果 shape 中消失。** 它不是指定“保留哪个轴”。

- `dim=0`：把两行对应位置合并，得到每列的总和或均值，列的位置保留。
- `dim=1`：把每行内部的三个位置合并，得到每行的总和或均值，行的位置保留。
- 不指定 `dim`：这里把全部元素汇总，得到一个 0 维张量。

比如 `sum(dim=0)` 中，第一列算 `1+4`，第二列算 `2+5`，第三列算 `3+6`；不是把“第 0 行”单独加起来。

## 6. keepdim：让归约结果接回广播

`keepdim=True` 会把被汇总的轴**保留为长度 1**，而不是保留它原来的长度：

```text
A.sum(dim=1)                 → [6, 15]       shape: (2,)
A.sum(dim=1, keepdim=True)   → [[6], [15]]   shape: (2, 1)
A.sum(dim=0, keepdim=True)   → [[5, 7, 9]]   shape: (1, 3)
```

为什么保留一个长度为 1 的轴？因为这些汇总结果常常还要与原张量运算。

例如，让每一行除以自己的总和：

```python
totals = A.sum(dim=1, keepdim=True)  # (2, 1)
result = A / totals                # (2, 3)
```

结果是 `[[1/6, 2/6, 3/6], [4/15, 5/15, 6/15]]`。如果省略 `keepdim=True`，总和变成 `(2,)`，就不能直接与 `(2, 3)` 广播。

再看**每行减去自己的均值**：

```python
row_mean = A.mean(dim=1, keepdim=True)  # [[2], [5]]，(2, 1)
result = A - row_mean                 # (2, 3)
```

```text
[[1, 2, 3],       [[2, 2, 2],       [[-1, 0, 1],
 [4, 5, 6]]   -    [5, 5, 5]]   =    [-1, 0, 1]]
```

每行的平均值变成 0，这叫按行**中心化**。这里只做了减均值，不等于完成所有意义上的“归一化”。如果要按列中心化，则沿 `dim=0` 求均值并保留轴，均值 shape 为 `(1, 3)`。

归约后保留长度 1，既保留了轴的位置，也让广播沿预期的方向发生。

## 7. loss 的陷阱：一个标量也可能是错的

设三个样本的预测值和目标值分别为：

```text
pred   = [[1], [2], [3]]    shape: (3, 1)
target = [1, 2, 3]          shape: (3,)
```

每个预测都等于对应目标，逐样本比较的均方误差应该是 0。但直接写：

```python
loss = ((pred - target) ** 2).mean()
```

先看相减发生了什么：

```text
pred：   (3, 1)
target： (1, 3)    ← 判断时补齐
结果：   (3, 3)

pred - target = [[0, -1, -2],
                 [1,  0, -1],
                 [2,  1,  0]]
```

原本想做三次对应比较，却变成了**每个预测与所有目标都比较一次**。平方后的元素总和为 12，共有 9 个元素，所以最终得到 `12/9 ≈ 1.33`，而不是 0。

程序没有报错，loss 也是标量，但目标已经变了。**`mean()` 只能汇总前面的计算结果，不能修复广播已经造成的两两比较。**

在这个逐样本比较的例子中，应先把两边组织成一致的 shape，例如都为 `(3, 1)`。三个对应误差都是 0，均方误差才是 0。元素数量相等，本身不能保证位置一一对应。

## 小结与自检

排查张量运算时，按这个顺序走：**输入 shape → 广播后的 shape → 归约的轴与最终 shape**。不要只检查结果能否运行，或最后是不是一个数。

1. `(2, 3)` 能直接加 `(2,)` 吗？**答：不能。右对齐后先比较 3 和 2，既不相等，也没有 1。**
2. `(2, 3, 4)` 与 `(3, 1)` 相加，结果是什么 shape？**答：后者按 `(1, 3, 1)` 判断，结果为 `(2, 3, 4)`。**
3. 对 `(2, 3)` 的浮点张量，每列减去各自均值，均值怎样求？**答：`A.mean(dim=0, keepdim=True)`，shape 为 `(1, 3)`。**
4. 为什么 `(3, 1)` 和 `(3,)` 的差再求均值，可能出错？**答：相减先广播成 `(3, 3)`；之后求均值只是汇总了错误的配对结果。**
