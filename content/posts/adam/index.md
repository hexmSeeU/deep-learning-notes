[Momentum]({{< relref "/posts/momentum" >}})让更新参考历史梯度。这一节继续问：**能不能参考每个参数自己的历史梯度大小，分别调整更新尺度？**

## 1. 同一个学习率，不同参数可能走得很不一样

假设两个参数 a、b 的当前梯度分别为 100、1。普通 SGD 使用学习率 0.01，调整量就是 −1、−0.01，幅度相差 100 倍。

这不一定有问题。但如果 a 的方向容易走过头，把共同学习率降到 0.001，调整量变成 −0.1、−0.001，b 也一起变慢，两者比例没变。

Adam 的思路是：**保留共同的基础学习率，同时根据每个参数自己的历史信息，分别缩放更新。** 它为此维护两个状态 m、v。

## 2. 一阶矩 m：梯度的指数移动平均

```text
mₜ = β₁mₜ₋₁ + (1−β₁)gₜ
```

g 是本步梯度，β₁ 控制历史保留程度。这就是上一节的平均形式，每个参数各自维护自己的状态。

取 m₀=0、β₁=0.9，假设连续两步梯度为 2、−1：

```text
m₁ = 0.9×0 + 0.1×2 = 0.2
m₂ = 0.9×0.2 + 0.1×(−1) = 0.08
```

第二步当前梯度已为负，m 却仍为正，因为历史正向贡献尚未被抵消。这里要代入上一轮状态 0.2，不能把它当作上一轮原始梯度 2。

m 叫**一阶矩估计**。先把名字对应到操作：它是梯度的指数移动平均，保留正负号，同向贡献叠加，反向贡献抵消。

## 3. 二阶矩 v：先平方，再做移动平均

```text
vₜ = β₂vₜ₋₁ + (1−β₂)gₜ²
```

为了方便手算，本篇取 β₂=0.9、v₀=0，继续用梯度 2、−1：

```text
v₁ = 0.9×0 + 0.1×2² = 0.4
v₂ = 0.9×0.4 + 0.1×(−1)² = 0.46
```

| 状态 | 平均的对象 | 正负贡献会抵消吗？ |
| --- | --- | --- |
| m | 梯度 g | 会 |
| v | 梯度平方 g² | 不会因正负号抵消 |

如果第二步梯度换成 −2，v₂ 就是 `0.36+0.4=0.76`。

**m 记录方向趋势，v 记录近期梯度的平方大小。** v 不是二阶导数，也不是先对梯度取平均再平方。本节 v 与上一节 Momentum 的 v 含义不同，符号要结合公式看。

## 4. 为什么用 m 除以 √v？

先暂时不加偏差修正，观察核心结构：

```text
调整量 = −η × m / (√v + ε)
```

开平方把“梯度平方的尺度”变回“梯度的尺度”。假设两个参数第一步梯度分别为 100、1，状态从零开始，β₁=β₂=0.9：

| 参数 | 梯度 | m | v | m/√v，忽略 ε |
| --- | ---: | ---: | ---: | ---: |
| a | 100 | 10 | 1000 | 约 0.316 |
| b | 1 | 0.1 | 0.1 | 约 0.316 |

较大的 m 配上了较大的分母，缩放后结果相同。这里两个参数各有自己的 v，不是共用一个全局分母。

这只是展示缩放原理，还不是完整 Adam，也不意味着训练中所有参数的更新幅度总相等。

## 5. 偏差修正：补上从零开始时不足的权重

若梯度一直为 2、β₁=0.9，从 m₀=0 开始会得到：

```text
m₁ = 0.2
m₂ = 0.38
```

梯度始终是 2，m 却从很小的数慢慢接近 2，因为前几步积累的权重还不够：

```text
m₁ = 0.1×2
m₂ = (0.1+0.09)×2
```

Adam 对两个零初始化状态分别修正：

```text
m̂ₜ = mₜ / (1−β₁ᵗ)
v̂ₜ = vₜ / (1−β₂ᵗ)
```

t 是当前第几次更新，βᵗ 表示 β 的 t 次方。于是：

```text
m̂₁ = 0.2 / (1−0.9) = 2
m̂₂ = 0.38 / (1−0.9²) = 2
```

对于第一步 v₁=0.4：

```text
v̂₁ = 0.4 / (1−0.9) = 4
√v̂₁ = 2
```

注意修正后的 v̂ 是 4，对应梯度的平方，不是梯度本身。修正消除的是零初始化造成的权重不足，**不是保证准确预测未来梯度**。梯度变化时，它仍是历史信息的加权估计。

完整更新为：

```text
θₜ = θₜ₋₁ − η × m̂ₜ / (√v̂ₜ + ε)
```

## 6. 手算两步：更新并不固定等于学习率

设初始 θ=5，η=0.01，β₁=β₂=0.9，m₀=v₀=0。两个 β 都取 0.9 是手算设置。

第一步梯度为 2：

```text
更新状态：m₁=0.2，v₁=0.4
偏差修正：m̂₁=2，v̂₁=4
更新参数：θ₁=5−0.01×2/(√4+ε) ≈ 4.99
```

同学习率的普通 SGD 会得到 `5−0.01×2=4.98`。两种优化器不能仅凭学习率相同，就要求走一样远。

如果从零状态重新开始，把第一步梯度换成 200，修正后 m̂₁=200、v̂₁=40000，忽略 ε，比值仍为 1。Adam 第一步的调整量不会放大 100 倍。

但后续不一定如此。沿第一步梯度为 2 的例子继续，假设第二步在新位置算出梯度 −2：

```text
m₂ = 0.9×0.2 + 0.1×(−2) = −0.02
v₂ = 0.9×0.4 + 0.1×(−2)² = 0.76

m̂₂ = −0.02/(1−0.9²) ≈ −0.1053
v̂₂ = 0.76/(1−0.9²) = 4

调整量 ≈ −0.01×(−0.1053)/2 ≈ +0.000526
```

虽然当前梯度大小仍是 2，移动却小了很多：**m 中的正负贡献抵消，v 中的平方贡献没有抵消。** Adam 同时考虑方向是否持续一致，以及近期梯度尺度有多大。

## 7. ε 不只是一处可以省略的小数

ε 是很小的正数，用于避免分母为零。若梯度从开始就一直为 0，那么 m̂=v̂=0；不加 ε 会出现 0/0，加上后更新为 0。

从零状态开始，第一步可写成：

```text
调整量 = −η × g/(|g|+ε)
```

只有当 |g| 远大于 ε，比值才接近 +1 或 −1。若 g=ε＞0，比值为 1/2，调整量为 **−η/2**：幅度是半个学习率，方向是参数减小。

所以不能把 Adam 当作“无论梯度多小，每步都固定移动一个学习率”。

## 8. 更新流程对应到代码

```python
optimizer = torch.optim.Adam(
    [w, b],
    lr=0.01,
    betas=(0.9, 0.9),
    eps=1e-8,
)
```

lr 对应 η，betas 对应 β₁、β₂，eps 对应 ε。这里明确写出手算设置，不把它当成默认配置或通用推荐。

训练流程仍然是：

```python
optimizer.zero_grad(set_to_none=True)

pred = w * 50.0 + b
loss = (pred - 150.0) ** 2

loss.backward()
optimizer.step()
```

step 内部读取梯度，更新每个参数的 m、v 和步数，做偏差修正与尺度缩放，再修改参数。跨步保存的是状态与计数，修正后的量可由它们计算。

**换优化器不会改变同一位置、同一数据和损失的数学梯度。** backward 负责求导，区别在于优化器如何使用导数。

优化器应在循环外创建，保留历史状态。zero_grad 只清 .grad，不清 m、v 和步数。

## 小结与自检

```text
当前梯度 → 更新 m、v → 偏差修正 → 按各参数尺度缩放 → 更新参数
```

1. 二阶矩 v 是二阶导数吗？**答：不是，它是梯度平方的指数移动平均。**
2. 方向反转时，为什么更新可能变小？**答：m 中的贡献可能抵消，v 中的平方贡献不会因符号抵消。**
3. 偏差修正解决什么？**答：零初始化让早期积累的权重不足，需要分别除以 1−β₁ᵗ、1−β₂ᵗ。**
4. 同样位置换用 Adam，backward 的梯度会改变吗？**答：不会，变化的是使用梯度的更新规则。**
