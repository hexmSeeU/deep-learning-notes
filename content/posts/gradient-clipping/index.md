[上一节]({{< relref "/posts/learning-rate-scheduling-and-warmup" >}})讨论了怎样随训练进度安排学习率。但即使学习率不变，偶尔出现的大梯度，仍可能造成突然的大步更新。

本节关注：**求出梯度后，能否先限制它，再交给优化器？**

## 1. 裁剪发生在求导之后、更新之前

先用不带动量的普通 SGD：

```text
参数调整量 = −学习率 × 梯度
```

学习率为 0.01，连续三次梯度为 2、3、1000，对应的本步调整量分别为 −0.02、−0.03、−10。前两步很小，第三步却可能跳出原本较好的区域，让后续计算不稳定。

梯度大并不自动证明有错。这里关注的是更新风险：**先检查梯度大小，超限时缩小它，再更新参数。**

```text
前向 → 损失 → backward 求梯度 → 裁剪 → optimizer.step 更新
```

裁剪不修改本轮已经算出的预测和损失，也不直接修改参数值；它处理的是即将用于更新的梯度。

## 2. 整体范数裁剪：缩短向量，保持方向

假设两个标量参数的梯度为 `g=[3,4]`。用 L2 范数衡量整体大小：

```text
‖g‖₂ = √(3²+4²) = 5
```

把梯度看成向量，分量给出方向，范数表示长度。若最大范数为 2，就把所有分量乘同一个比例：

```text
缩放比例 = 2/5 = 0.4
裁剪后梯度 = [1.2,1.6]
新范数 = √(1.2²+1.6²) = 2
```

分量比例仍是 3:4，方向不变。一般规则是：

```text
范数超过阈值：所有分量乘以 最大范数/当前范数
范数没有超限：原样保留
```

例如 `[0.3,0.4]` 的范数为 0.5，小于 2，无需裁剪。**裁剪只缩小超限梯度，不会把小梯度放大到阈值。**

### 参数是张量，梯度也可以有很多元素

讨论中有一个疑问：为什么某个参数的 grad 里会有多个数？因为参数本身可能是向量或矩阵。

```text
A = [a₁,a₂]，shape 为 (2,)
A.grad = [∂L/∂a₁,∂L/∂a₂]
```

梯度与参数 shape 相同，元素一一对应。shape 为 (3,4) 的权重矩阵，就有 12 个梯度元素。

如果模型只有一个标量参数 a 和一个 (3,4) 的矩阵 W，整体范数就把它们共 13 个梯度分量一起平方、求和、开平方。

## 3. “整体”必须明确：到底选了哪些参数？

裁剪范围由我们指定，通常选择全部可训练参数，也可以只选一部分。**整体范数是把选定范围内已有的梯度放在一起计算，不是每个张量分别限制。**

例如：

```text
A.grad = [3,0]
B.grad = [0,4]
```

合起来看成 `[3,0,0,4]`，范数为 5。整体限制到 2，结果是：

```text
A.grad → [1.2,0]
B.grad → [0,1.6]
```

若分别把 A、B 的范数各裁到 2，则会得到 `[2,0]` 与 `[0,2]`：合起来范数约 2.83，非零分量比例也从 3:4 变成 1:1。**分别裁剪不等于整体裁剪。**

同样，如果选中 a、b，没有选 c：

```text
原梯度：a.grad=3，b.grad=4，c.grad=100
只对 a、b 整体限制到 2：
结果：  a.grad=1.2，b.grad=1.6，c.grad=100
```

未选入的参数不受影响，`.grad is None` 的参数也没有梯度可裁。

在选定范围内，只要整体超限，即使某个分量本来很小，也要一起缩放。例如整体范数为 5、阈值为 2，a.grad=0.1 也会变成 0.04。这样才能保持整个向量的方向。

## 4. 逐元素裁剪：限制各分量，可能改变方向

另一种方式是直接给各分量设上下限，例如 `[-2,2]`：

```text
[3,4]    → [2,2]
[0.5,−5] → [0.5,−2]
```

范围内不变，超过上限就取上限，低于下限就取下限。

| 方式 | 限制什么 | [3,4] 的结果 |
| --- | --- | --- |
| 整体范数裁剪 | 整个向量长度不超过 2 | [1.2,1.6] |
| 逐元素裁剪 | 各分量都在 [-2,2] | [2,2] |

逐元素裁剪后，3:4 变成 1:1，方向改变；整体范数约 2.83，也不保证小于 2。**阈值数字相同，不代表限制的是同一个对象。**

## 5. 为什么不直接降低学习率？

用普通 SGD 对照。学习率 0.1、最大范数 2：

| 梯度 | 范数裁剪后的梯度 | 最终调整量 |
| --- | --- | --- |
| [0.3,0.4] | 不变 | [−0.03,−0.04] |
| [3,4] | [1.2,1.6] | [−0.12,−0.16] |

如果不裁剪，把学习率统一降到 0.04：

```text
[0.3,0.4] → 调整量 [−0.012,−0.016]
[3,4]     → 调整量 [−0.12,−0.16]
```

这次大梯度效果恰好相同，但小梯度也一起缩小了。因此：

- 降低学习率：相同梯度下，所有更新都按比例缩小。
- 范数裁剪：只处理超限梯度，正常小梯度保持原样。

对不带动量的普通 SGD，选定范围内还有：

```text
更新向量的范数 ≤ 学习率 × 最大梯度范数
```

例如学习率 0.1、阈值 2，更新长度不超过 0.2。**这个直接关系不能照搬到 Momentum、Adam**，它们还会使用历史状态或缩放梯度。限制输入梯度，不等于直接限制最终更新幅度。

## 6. PyTorch 中的范围与执行位置

沿用 w、b 两个标量参数：

```python
optimizer.zero_grad(set_to_none=True)

pred = w * 50.0 + b
loss = (pred - 150.0) ** 2
loss.backward()

# 把 w、b 的已有梯度作为一个整体，限制 L2 范数
torch.nn.utils.clip_grad_norm_([w, b], max_norm=2.0)

optimizer.step()
```

虽然传入的是 `[w,b]`，修改的是它们的 `.grad`。执行裁剪后、step 前，参数值仍未改变。只传 `[w]`，b 就既不参与范数计算，也不受裁剪影响。

完整模型通常传入：

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=2.0)
```

这里的 2 只是演示，不是通用阈值推荐。

## 7. 梯度累积：汇总完整后，通常只裁一次

若一次更新使用多组样本，目的是限制这次更新的完整梯度，那么顺序应为：

```text
清梯度 → 各组正确加权并反向累积 → 裁剪一次 → 更新一次
```

为什么不分别裁剪每组再平均？看一个标量例子，两组大小相等，组平均损失的梯度分别为 10、−8，阈值为 2：

```text
先平均再裁： (10−8)/2 = 1，未超限，保留 1
分别裁再平均：(2−2)/2 = 0
```

结果不同，因为裁剪改变了各组贡献的相对大小。分别裁剪不能当成对合并后的平均梯度裁剪。

沿用上一节的规则，等大两组可各用一半损失反向，得到 `(g₁+g₂)/2`；组大小不同时要按样本数加权。**先把本次更新的梯度算完整，再统一裁剪。** 累积 4 个 batch 后更新一次，就在更新前裁剪一次。

## 小结与自检

核心是分清三个问题：**选哪些参数、怎样限制梯度、何时执行裁剪。** 裁剪改变梯度，参数更新仍由优化器完成。

1. 整体超限时，本来很小的梯度分量会缩小吗？**答：在选定范围内，也按同一比例缩小。**
2. 逐元素限制到 [-2,2]，整体范数就不超过 2 吗？**答：不保证，例如 [2,2] 的范数约为 2.83。**
3. 裁剪之后、step 之前，参数值改变了吗？**答：没有，改变的是 .grad。**
4. 累积 4 组后更新一次，通常裁几次？**答：先正确累积完整，再裁剪一次。**
