[Adam]({{< relref "/posts/adam" >}})会根据各参数的历史梯度缩放更新，为什么还要调学习率？因为**优化器决定怎样使用梯度，基础学习率仍控制整体步幅**。

## 1. 调度改变的是基础学习率

把 Adam 更新暂时写成：

```text
rₜ = m̂ₜ / (√v̂ₜ + ε)
调整量 = −ηₜ × rₜ
```

若当前两个参数的 r 分别为 0.5、−0.2，学习率从 0.01 降到 0.001，调整量就从 `−0.005、+0.002` 变成 `−0.0005、+0.0002`。

在 r 不变时，减小学习率会同比缩小幅度，不改变方向。**学习率调度**就是让 η 随训练进度变化，而不是一直固定。

## 2. 为什么后期可能需要小步细调？

先看普通梯度下降的例子 `L(θ)=θ²`，最小值在 0，梯度为 2θ：

```text
θ新 = θ − η×2θ = (1−2η)θ
```

从 θ=1 出发：

| 学习率 | 第一次移动 | 连续位置 |
| --- | --- | --- |
| 0.75 | 移动 −1.5，越过 0 | 1 → −0.5 → 0.25 → −0.125 |
| 0.25 | 移动 −0.5，留在原侧 | 1 → 0.5 → 0.25 → 0.125 |

为什么每步都如此？当 θ≠0，调整幅度与距离 0 的比值始终是：

```text
|−2ηθ| / |θ| = 2η
```

η=0.75 时，每次移动距离的 1.5 倍，总会越过 0；η=0.25 时只移动距离的一半，不会跨过。η=0.5 则从 1 一步到 0。

这些界限来自这个具体函数。这里两条轨迹离 0 的距离恰好缩小得一样快，**不能得出学习率越小越快**。

实际 mini-batch 梯度还会波动。到了较好区域，较大步幅可能让参数持续来回移动，降低学习率有助于细调。但一开始就设得很小，也可能推进缓慢；调小不保证每次都更好。

## 3. 分段与余弦：两种预设安排

### 分段衰减

例如计划更新 1000 次：

| 更新次数 | 学习率 |
| --- | ---: |
| 1～500 | 0.01 |
| 501～800 | 0.001 |
| 801～1000 | 0.0001 |

到预定位置，就降低学习率。即使第 500 次损失还在明显下降，第 501 次仍会按表降低。

**这是按进度执行的计划，不是模型检测到了最优点。** 数值只用于展示，并非通用推荐。

### 余弦衰减

也可以让变化更平滑。设这段调度长度为 T，进度 t 从 0 到 T：

```text
η(t) = η最小 + ½(η最大−η最小)×[1+cos(πt/T)]
```

从 0.01 降到 0.001：

| 进度 | 学习率 |
| --- | ---: |
| 开始，t=0 | 0.01 |
| 一半，t=T/2 | 0.0055 |
| 结束，t=T | 0.001 |

中点是最大值与最小值的平均，不是把最大值直接除以 2。余弦曲线在开头、结尾下降较缓，中间较快。

平滑不等于一定更好，它仍是预设安排，不会自动判断当前学习率是否最合适。

## 4. Warmup：先小步起跑，再升到目标值

Warmup 在训练开始的一小段时间，用较小学习率逐渐升到目标值。例如目标为 0.001，前 100 次更新线性升高：

```text
第 1 次：  0.00001
第 50 次： 0.0005
第 100 次：0.001
```

训练刚开始时，参数处于初始化附近，Adam 的历史状态也刚建立，梯度和更新尺度可能变化较快。Warmup 限制最初步幅，提供较温和的起步过程，是一种稳定手段，并非所有任务都必须使用。

| 机制 | 做什么 |
| --- | --- |
| Adam 偏差修正 | 修正 m、v 零初始化造成的权重不足 |
| Warmup | 主动改变基础学习率，让初期更新更小 |

两者不能互相替代。**Warmup 期间仍正常前向、求梯度和更新参数**，不是暂停学习。

## 5. 接上衰减，要计算各阶段自己的进度

假设总共更新 1000 次，前 100 次 warmup，之后 900 次余弦衰减，从 0.001 降到 0.0001。

在“已完成多少次更新”的曲线上定义：

```text
s = 已完成的更新次数 − 100
η = 0.0001 + ½(0.001−0.0001)×[1+cos(πs/900)]
```

| 已完成更新 | 衰减进度 | 曲线上的学习率 |
| --- | --- | ---: |
| 100 | s=0，刚开始 | 0.001 |
| 550 | s=450，衰减一半 | 0.00055 |
| 1000 | s=900，衰减结束 | 0.0001 |

已完成 500 次更新时，衰减只走了 400/900=4/9。**全程一半，不等于衰减阶段一半。**

曲线上的位置与“下一次 step 使用哪个值”还要在代码中明确对应，不能把已完成更新数与本次更新编号混着代入。

## 6. 调度步数要跟参数更新同步

[梯度累积]({{< relref "/posts/mini-batch-and-sgd" >}})会让 batch 数与更新次数不同。例如每个 epoch 有 12 个 batch，每累积 3 组更新一次：

```text
batch 1、2、3    → 参数更新一次 → 调度推进一次
batch 4、5、6    → 参数更新一次 → 调度推进一次
batch 7、8、9    → 参数更新一次 → 调度推进一次
batch 10、11、12 → 参数更新一次 → 调度推进一次
```

一遍处理 12 个 batch，只更新 4 次。若按更新次数规划了 100 步 warmup，却每个 batch 都推进一次，warmup 就被提前消耗了。

| 调度单位 | 何时推进 |
| --- | --- |
| 按参数更新次数 | 每次实际更新参数时 |
| 按 epoch | 每完整遍历一轮数据时 |

两种安排都可以，关键是配置、公式与调用使用同一单位。本节始终按更新次数讨论。每累积 4 组更新一次，100 次 warmup 更新就需要处理 400 个 batch，假设各组完整且没有跳过更新。

## 7. 手动设置，明确本次更新用哪个学习率

先不用调度器 API，假设已创建好优化器，手动实现刚才的 100 次线性 warmup：

```python
warmup_steps = 100
target_lr = 0.001

for update in range(1, 101):
    lr = target_lr * update / warmup_steps
    for group in optimizer.param_groups:
        group["lr"] = lr

    optimizer.zero_grad(set_to_none=True)
    pred = w * 50.0 + b
    loss = (pred - 150.0) ** 2
    loss.backward()
    optimizer.step()
```

param_groups 保存优化器的参数组与配置。这段代码给各组设置同一个 lr，顺序是：**确定本次学习率 → 设置配置 → 求导 → 按此学习率更新。**

因此，第 1、50、100 次 step 分别使用 0.00001、0.0005、0.001。

这里只修改已有优化器的配置，没有重新创建它。使用 Adam 时，之前保存的 m、v 和步数仍然保留。

## 小结与自检

调度安排基础学习率，warmup 负责温和起步；两者都必须明确阶段进度与计数单位，不能把 batch 数直接当成更新次数。

1. 分段降低学习率说明检测到了最优点吗？**答：不能，它只是执行预设进度。**
2. Warmup 期间更新参数吗？**答：正常更新，只是学习率较小且逐渐升高。**
3. 总共 1000 次更新，前 100 次 warmup，衰减一半在哪？**答：已完成 550 次更新的位置。**
4. 修改学习率会清掉 Adam 的状态吗？**答：不会，改变配置不等于重建优化器。**
