[上一节]({{< relref "/posts/training-objective" >}})明确了训练目标：寻找让训练数据平均损失更小的参数。这一节先用一条房价样本，完成一次更新，再把它接成训练循环。

## 1. 梯度不是调整量，还要乘学习率

沿用面积 x=50、实际价格 y=150，模型 `ŷ=wx+b`。当前 w=2、b=10，预测为 110，平方误差为 1600。

```text
L(w,b) = (50w+b−150)²

∂L/∂ŷ = 2(110−150) = −80
∂L/∂w = −80×50 = −4000
∂L/∂b = −80×1  = −80
```

w 对预测的影响要乘输入 50，b 则直接加上去，因此两个偏导数相差 50 倍。负号说明，在当前位置单独小幅增大 w 或 b，都能降低损失。

梯度下降把变化率转成实际调整量：

```text
新参数 = 当前参数 − 学习率 × 当前梯度
```

选择学习率 η=0.0001：

```text
w新 = 2  − 0.0001×(−4000) = 2.4
b新 = 10 − 0.0001×(−80)   = 10.008

新预测 = 2.4×50+10.008 = 130.008
新损失 = (130.008−150)² ≈ 399.68
```

**两个参数都使用更新前同一位置的梯度。** 不是先更新 w，再用新 w 求 b 的梯度。负梯度决定方向，学习率决定走多远；这里的数值不是通用学习率。

## 2. 方向合理，步子仍可能太大

如果从同样的初始参数出发，把学习率放大十倍到 0.001，调整量也放大十倍：w 变成 6，b 变成 10.08。

| 独立尝试 | 更新后预测 | 损失 |
| --- | ---: | ---: |
| 更新前 | 110 | 1600 |
| 学习率 0.0001 | 130.008 | 约 399.68 |
| 学习率 0.001 | 310.08 | 约 25625.61 |

原本预测偏低，提高预测是合理方向，但大步更新让它越过了目标，变得严重偏高。**负梯度是当前位置的下降方向，不保证沿它走任意远都下降。** 更新后损失变大，不能直接断定梯度算错。

每轮还必须重新求梯度。沿较小学习率继续，第一次更新后误差为 −19.992，新梯度变为：

```text
∂L/∂w = 2×(−19.992)×50 = −1999.2
∂L/∂b = 2×(−19.992)    = −39.984
```

第二次更新后 w=2.59992、b=10.0119984，预测约 140.008，损失约 99.84。学习率没变，梯度变小，调整量也随之变小。

## 3. 手动更新：no_grad 与清空梯度各管什么？

```python
import torch

w = torch.tensor(2.0, requires_grad=True)
b = torch.tensor(10.0, requires_grad=True)

pred = w * 50.0 + b
loss = (pred - 150.0) ** 2
loss.backward()  # w.grad=-4000，b.grad=-80；参数值尚未改变

with torch.no_grad():
    w -= 0.0001 * w.grad
    b -= 0.0001 * b.grad

w.grad = None
b.grad = None
```

讨论中的一个疑问是：**最后已经清空 `.grad`，为什么还要 no_grad？**

它们处理的是不同环节：

- `no_grad()`：执行数值修改，但不把这次更新记录为求导运算。这里对需要梯度的叶子参数直接进行原地修改，若不关闭记录会报错，程序到不了后面的清空操作。
- `.grad = None`：清掉已经保存的梯度结果，避免下次反向时累加旧梯度。它不会撤销计算图，也不会让之前不允许的修改变合法。

**清空梯度不会把 w 恢复成 2。** w 仍是更新后的约 2.4，`requires_grad` 也仍是 True。离开 no_grad 后，下一轮前向又会记录新的求导关系。

## 4. 优化器：把更新操作交出去

这里使用不带动量等额外机制的 `torch.optim.SGD`，替代上面的手动更新，并组成最小循环：

```python
import torch

w = torch.tensor(2.0, requires_grad=True)
b = torch.tensor(10.0, requires_grad=True)
optimizer = torch.optim.SGD([w, b], lr=0.0001)

for step in range(3):
    optimizer.zero_grad(set_to_none=True)

    pred = w * 50.0 + b
    loss = (pred - 150.0) ** 2

    loss.backward()
    optimizer.step()
```

| 操作 | 职责 |
| --- | --- |
| `zero_grad(...)` | 清空优化器管理的参数梯度 |
| `loss.backward()` | 在当前位置求梯度，不改变参数值 |
| `optimizer.step()` | 使用已有梯度更新参数，不替我们求导 |

这个常规调用中，优化器会处理更新时不记录求导关系的问题，无需再手动包 no_grad。清空梯度放在本轮求导前，与放在上一轮更新后，都是为了避免旧结果混入。

### set_to_none 不设置会怎样？

当前 PyTorch 默认 `set_to_none=True`，所以 `optimizer.zero_grad()` 与显式传 True 效果相同。设为 False 则把**已有的梯度张量**清零，不会给原本为 None 的梯度创建零张量。

```text
True： w.grad → None
False：已有的 w.grad → 零张量
```

两者清的都是梯度，不是参数。当前例子每轮都会给 w、b 求出梯度，两种写法都能避免旧梯度累加。

但若某个参数本轮没有得到梯度，None 会让优化器跳过它，零张量则按零梯度参与处理；在带动量或权重衰减时可能产生不同结果，后面再展开。True 通常也能减少梯度存储开销。默认行为可核对 [PyTorch zero_grad 文档](https://docs.pytorch.org/docs/stable/generated/torch.optim.Optimizer.zero_grad.html)。

## 5. 参数更新了，旧 loss 不会自动重算

第一轮计算 loss 时，参数还是 w=2、b=10，因此 loss 为 1600。执行 step 后参数变了，但旧 pred、loss 不会随之刷新。

若要立即查看第一轮更新后的损失，需要重新前向：

```python
# 接在第一轮 optimizer.step() 后执行
with torch.no_grad():
    new_pred = w * 50.0 + b
    new_loss = (new_pred - 150.0) ** 2

print(new_loss.item())  # 约 399.68
```

所以在 step 后直接打印旧 `loss.item()`，通常仍是本轮更新前的损失。这不是错误，只要知道它对应哪个时刻。

同样，旧 loss 对应旧参数处的计算。不能对它再反向，就期待得到新位置的梯度；下一轮要重新计算 pred 和 loss。

## 小结与自检

```text
清旧梯度 → 当前参数做预测 → 计算损失 → 求梯度 → 更新参数
    ↑                                                 │
    └────────── 新参数处重新前向、求导 ─────────────────┘
```

1. 学习率固定，每次调整量也固定吗？**答：不固定，当前梯度可能变化。**
2. backward 后、step 前，参数改了吗？**答：没有，求导与更新是两个操作。**
3. no_grad 与 zero_grad 能互相替代吗？**答：不能，前者控制记录，后者清空梯度结果。**
4. step 后旧 loss 会自动变成更新后的损失吗？**答：不会，需要用新参数重新前向计算。**
